# Markdown DOCX Exporter

Локальный proof-of-concept плагин Obsidian для обмена между Markdown и `.docx` через Pandoc.

## Задача

Проверить рабочую схему:

```text
Obsidian Markdown -> Pandoc -> Word DOCX
Word DOCX -> Pandoc -> Obsidian Markdown
```

Это не редактор `.docx` внутри Obsidian. Плагин нужен, чтобы писать текст в `.md`, а затем получать нормальный Word-документ без открытия Markdown как обычного текстового файла.
Обратный импорт нужен, чтобы уже существующий `.docx` можно было перенести в Markdown без ручного копирования через Word.

## Требования

- Windows.
- Obsidian Desktop.
- Pandoc в системе. По умолчанию используется команда `pandoc`.

## Команды

- `Export active Markdown to DOCX` - экспортирует текущую Markdown-заметку в `.docx`.
- `Import active DOCX to Markdown` - импортирует текущий `.docx` в Markdown-заметку.

Если файл с таким именем уже открыт в Word и Windows не даёт его перезаписать, плагин создаёт новый файл с номером, например:

```text
Название документа (2).docx
```

## Настройки

- `Pandoc path` - путь к `pandoc.exe` или команда `pandoc`, если Pandoc доступен из PATH.
- `Output folder` - папка внутри хранилища для готовых `.docx`.
- `DOCX import folder` - папка внутри хранилища для импортированных `.md`.
- `Reference DOCX` - необязательный путь к Word-шаблону стилей. Если поле пустое, используется встроенный обычный академический шаблон.
- `Use built-in plain DOCX template` - применяет встроенный `reference.docx`: Times New Roman, 12 pt, чёрный текст, сноски 10 pt.
- `Body font size` - размер основного текста в пунктах. Вводится числом, например `12`. Применяется в резервной Word-нормализации.
- `Footnote font size` - размер текста сносок в пунктах. Вводится числом, например `10`. Применяется в резервной Word-нормализации.
- `Normalize typography with Word` - рекомендуемый режим, включён по умолчанию: после экспорта Word сам применяет Times New Roman, размеры основного текста и сносок, размеры заголовков и корректные надстрочные знаки сносок.
- `Open DOCX after export` - открыть результат системным приложением после экспорта.
- `Open Markdown after DOCX import` - открыть импортированную Markdown-заметку после преобразования.

## Текущий статус

Проверка концепции. Основные риски для дальнейшей доработки:

- Obsidian wikilinks требуют отдельной обработки.
- Callout-блоки требуют правил: экспортировать, преобразовывать или исключать.
- Для финальной журнальной/диссертационной вёрстки лучше иметь отдельный `reference.docx` с требованиями конкретного места подачи.
- Ссылки вида `[1]` остаются текстом; настоящие Markdown-сноски `[^1]` Pandoc умеет превращать в сноски Word.
- Obsidian-викиссылки перед экспортом очищаются для Word: `[[Библиография#^bib-dolgova-textbook|Долгова]]` превращается в `Долгова`.
- DOCX -> Markdown не может быть идеальной обратной операцией: Word хранит стили и разметку иначе, чем Markdown. Импорт переносит текст, заголовки, списки, сноски, таблицы в GFM/Obsidian-совместимом виде и базовое смысловое форматирование, но сложная Word-вёрстка требует проверки.
- Если Pandoc оставляет HTML-таблицу из-за объединённых ячеек Word, импорт дополнительно преобразует её в обычную pipe-таблицу Obsidian, чтобы не оставлять в заметке нечитаемый HTML.

## Номенклатурный DOCX-шаблон

По умолчанию плагин использует встроенный `reference.docx`, а затем безопасную Word-нормализацию. Это медленнее, чем чистый Pandoc, но нужно для приемлемого Word-результата:

- основной текст: Times New Roman, 12 pt;
- сноски: Times New Roman, 10 pt;
- номера сносок: надстрочные;
- заголовки: Times New Roman, увеличенный размер в зависимости от уровня;
- цвет шрифта: чёрный;
- без декоративных цветов и нестандартных шрифтов.

Смысловое форматирование Markdown сохраняется: жирный текст, курсив и подчёркивание не считаются декоративными элементами и должны переходить в `.docx`.

Подчёркивание в Markdown нужно задавать как HTML-фрагмент:

```markdown
<u>подчёркнутый текст</u>
```

Плагин подключает Pandoc Lua-фильтр, который превращает такой фрагмент в настоящее подчёркивание Word.

Настройка `Normalize typography with Word` не вскрывает `.docx` вручную: документ открывает и сохраняет сам Microsoft Word. Это медленнее, но безопаснее для структуры файла и необходимо для нормальных сносок.
