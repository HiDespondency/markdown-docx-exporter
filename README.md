# Markdown DOCX Exporter

Локальный proof-of-concept плагин Obsidian для экспорта активной Markdown-заметки в `.docx` через Pandoc.

## Задача

Проверить рабочую схему:

```text
Obsidian Markdown -> Pandoc -> Word DOCX
```

Это не редактор `.docx` внутри Obsidian. Плагин нужен, чтобы писать текст в `.md`, а затем получать нормальный Word-документ без открытия Markdown как обычного текстового файла.

## Требования

- Windows.
- Obsidian Desktop.
- Pandoc в системе. По умолчанию используется команда `pandoc`.

## Команды

- `Export active Markdown to DOCX` - экспортирует текущую Markdown-заметку в `.docx`.

## Настройки

- `Pandoc path` - путь к `pandoc.exe` или команда `pandoc`, если Pandoc доступен из PATH.
- `Output folder` - папка внутри хранилища для готовых `.docx`.
- `Reference DOCX` - необязательный путь к Word-шаблону стилей. Если поле пустое, используется встроенный обычный академический шаблон.
- `Use built-in plain DOCX template` - применяет встроенный `reference.docx`: Times New Roman, 12 pt, чёрный текст, сноски 10 pt.
- `Normalize typography with Word` - медленный резервный режим: после экспорта приводит документ через Microsoft Word к обычному виду.
- `Open DOCX after export` - открыть результат системным приложением после экспорта.

## Текущий статус

Проверка концепции. Основные риски для дальнейшей доработки:

- Obsidian wikilinks требуют отдельной обработки.
- Callout-блоки требуют правил: экспортировать, преобразовывать или исключать.
- Для финальной журнальной/диссертационной вёрстки лучше иметь отдельный `reference.docx` с требованиями конкретного места подачи.
- Ссылки вида `[1]` остаются текстом; настоящие Markdown-сноски `[^1]` Pandoc умеет превращать в сноски Word.

## Номенклатурный DOCX-шаблон

По умолчанию плагин использует встроенный `reference.docx`, чтобы Pandoc сразу создавал документ в обычном Word-виде:

- основной текст: Times New Roman, 12 pt;
- сноски: Times New Roman, 10 pt;
- заголовки: Times New Roman, увеличенный размер в зависимости от уровня;
- цвет шрифта: чёрный;
- без декоративных цветов и нестандартных шрифтов.

Смысловое форматирование Markdown сохраняется: жирный текст, курсив и подчёркивание не считаются декоративными элементами и должны переходить в `.docx`.

Подчёркивание в Markdown нужно задавать как HTML-фрагмент:

```markdown
<u>подчёркнутый текст</u>
```

Плагин подключает Pandoc Lua-фильтр, который превращает такой фрагмент в настоящее подчёркивание Word.

Настройка `Normalize typography with Word` оставлена только как резервный вариант. Она медленнее, потому что открывает Word через COM после экспорта.
